Большинство «скиллов дизайна» для агентов — замороженные наборы промптов: сильны в первый день, устаревают к тридцатому, и всегда несут вкус одного автора. **design-garden создан, чтобы его кормили** — вашей ежедневной дизайнерской работой и сообществом. Он не просто выполняет задачи дизайна; он **учится на каждой задаче, которую выполняет**.

## Что он делает

Всё ниже произведено скиллом при выполнении его собственных eval-задач — каждая работа прошла полный воркфлоу (включая критические ворота). Больше в [examples/](examples/README.md), вместе с исправлениями, которые нашли ворота.

## Чем он отличается: четыре цикла роста

1. **① Самообучение во время работы** — каждая задача добавляет структурированную запись в `learnings/<domain>.md`: он становится лучше лично для ВАС с каждым использованием, без переустановки
2. **② Вклад сообщества** — знание = маленькие модульные файлы. Один PR = один рецепт стиля / техника / кейс
3. **③ Продвижение через оценку (анти-раздувание)** — новое знание приходит как `experimental`, загружается только при явном совпадении и становится `proven` только после победы в слепом A/B-сравнении
4. **④ Версионированное обучение** — CHANGELOG каждой версии говорит, чему сад научился: рост, который можно прочитать

```
 ① каждая задача → опыт в learnings/
        ↓ (обобщаемые записи возвращаются upstream через PR)
 ② PR сообщества питают knowledge/
        ↓ (новое знание помечается experimental)
 ③ победа в слепом A/B → повышение до proven
        ↓
 ④ CHANGELOG записывает, чему научились
```

## Что внутри

```
SKILL.md                  роутер + воркфлоу из 8 шагов (≤500 строк — стабильное ядро)
knowledge/
  core/                   универсальные модули: принципы · цвет · типографика · макет · motion · анти-слоп
  domains/                9 доменов: ui-web · ui-mobile · постер/баннер · иконки · лого/бренд ·
                          слайды · data-viz · видео/ motion · иллюстрация (с чек-листом критики)
  styles/                 18 рецептов стилей (швейцарский, баухаус, нео-брутализм, глассморфизм,
                          dark-tech, y2k, джапанди, мемфис…) — по одному небольшому файлу
  case-studies/           до/после с рассуждением
learnings/                полевые заметки скилла — начинается с посева, растёт с каждой задачей
evals/                    бенчмарк-задачи с ловушками + рубрика + слепой A/B-инструмент
scripts/                  validate_knowledge.mjs (шлюз CI) · ab_harness.mjs (страницы слепых сравнений)
```

Роутер читает `knowledge/INDEX.md` и никогда не загружает больше ~7 файлов на задачу — **расти, не распухая**. Сам воркфлоу — дистилляция сильнейших процессных идей практики дизайна с агентами: **раздача трёх направлений**, **пять вопросов формы**, **ворота критики**, исправляющие только 3 самых вредных проблемы за раунд, и канонический **анти-слоп список**, слитый из трёх независимо сошедшихся источников. См. [SOURCES.md](SOURCES.md).

## Установка

Работает с любым агентом, поддерживающим конвенцию SKILL.md (ZCode, Claude Code и совместимые CLI):

```bash
# уровень пользователя (все проекты)
git clone https://github.com/iifzx/design-garden.git ~/.agents/skills/design-garden

# или уровень проекта
git clone https://github.com/iifzx/design-garden.git <ваш-проект>/.zcode/skills/design-garden
```

Без сборки и зависимостей — markdown плюс два опциональных Node-скрипта (только стандартная библиотека).

## Использование

Просто попросите дизайн. Скилл срабатывает на любую эстетическую задачу:

- «Сделай постер к открытию кафе в нашем районе» → раздаёт 3 направления, выполняет сильнейшее, критикует, сдаёт, записывает выученное
- «Спроектируй набор иконок для приложения по уходу за растениями» → keyline-сетки, оптические поправки, тесты силуэта
- «Этот постер выглядит странно — разбери» → режим ревью, чек-лист домена, исправления по убыванию вреда
- «Лендинг + набор шаблонов слайдов» → маршрутизирует оба домена, учится у обоих

## Вклад

**Сад растёт от маленьких PR.** Добавьте рецепт стиля, сообщите об опыте из собственного использования или проведите eval, чтобы повысить экспериментальное правило. Всё в [CONTRIBUTING.md](CONTRIBUTING.md) — кратко: форк, добавьте **один маленький файл** по схеме, `node scripts/validate_knowledge.mjs` должен пройти (CI требует), откройте PR. Знание сообщества начинается с `experimental` и становится `proven`, выигрывая слепое A/B-сравнение — рост **проверяется**, а не просто накапливается.
