# design-garden for DeepSeek Harness (dsh)

**English** | [简体中文](README.zh-CN.md)

A dsh **bundle plugin** that puts the [design-garden](../SKILL.md) skill into dsh's native skill catalog. Once installed, the model discovers it through the `skill` tool and loads it on demand for UI, posters, icons, logos, slides, charts, video storyboards and illustration work.

- **Package:** `dsh-design-garden`
- **Kind:** bundle plugin (skill provider), not a tool plugin — it adds no tools, commands or UI.
- **Exposes:** one skill, `design-garden`, at rank 600 (`bundled`).
- **Runtime deps:** none. Node builtins only.

## Install

Pick one path.

**From this checkout** (run at the repository root):

```sh
dsh plugin --profile web add file:./dsh
dsh web
```

**From Git, pinned to a commit** (replace `<40-hex-sha>`; never install a moving branch):

```sh
dsh plugin --profile web add "git+https://github.com/iifzx/design-garden.git#<40-hex-sha>&path:/dsh"
dsh web
```

**From the Discover tab** (dsh ≥ 0.2.1-alpha.4, experimental custom indexes): open **Plugins → Discover → Add index source** and enter:

```text
https://raw.githubusercontent.com/iifzx/design-garden/main/dsh/index.json
```

Then search for “Design Garden” and install the listed version. The index is generated by [`build-index.mjs`](build-index.mjs) and pins a commit.

## Verify

- **Skills list:** Settings → Skills (or the skill catalog) should show `design-garden`.
- **Config layer:** `dsh --profile web --dump-config` should contain a `design-garden-skills` row with `name: dsh-design-garden`.
- **End to end:** ask for a visual task (“design a poster for …”) and the agent should load the `design-garden` skill before acting.

## Why rank 600

dsh resolves same-name skills by rank within a layer: project roots (`.dsh/skills` = 100, `.agents/skills` = 200) beat user roots (`~/.dsh/skills` = 400, `~/.agents/skills` = 500), and both beat packaged skills (600). So a local checkout or a user-level copy always shadows this bundled copy — the plugin is a convenience, not a lock-in.

## Configuration

The default skill root is the copy shipped at `skills/` inside this package. Override it only if you want the plugin to serve a different checkout:

```yaml
# your profile's cordis.patch.yml
- id: design-garden-skills
  name: dsh-design-garden
  config:
    skillsDir: /absolute/path/to/design-garden
```

## What ships

| Path | Contents |
|---|---|
| `index.js` | Cordis plugin: registers one skill provider |
| `cordis.patch.yml` | Bundle patch that inserts the plugin row |
| `skills/design-garden/` | Packaged copy of `SKILL.md`, `knowledge/`, `learnings/`, `scripts/`, `VERSION` |
| `index.json` | dsh plugin index (format 1) for the Discover tab |
| `icon.svg` | Index icon |
| `build-index.mjs` | Rebuilds `index.json` from a Git commit |
| `sync-skills.mjs` | Mirrors the repo's runtime skill into `skills/design-garden/` |
| `test.mjs` | Offline provider smoke test |

The packaged skill is generated from the repository root; do not edit it by hand.

## Maintainer workflow

After changing the skill or bumping the plugin version:

```sh
node dsh/sync-skills.mjs      # refresh the packaged skill copy
node dsh/test.mjs             # provider smoke test
node dsh/build-index.mjs      # pin the latest commit that changed dsh/package.json
```

Commit the bundle first, then the regenerated index — the index pins the earlier commit that actually contains `dsh/`.

## Notes

- This plugin does not replace or modify the runtime skill at the repository root; it ships a copy so a Git/npm install is self-contained.
- Uninstall with `dsh plugin --profile web remove dsh-design-garden`.
