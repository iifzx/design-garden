# Learnings — poster-banner

Field notes recorded while working on poster/banner/social graphic tasks. Newest first. See `learnings/_TEMPLATE.md` for the schema.

## Entries

### 2026-11-16 | type-only event poster, "where" line almost failed the squint test
- Situation: quiet poster direction (80% emptiness) put the address at 26px in 90%-strength ink — invisible at blur distance
- Move: smallest line kept its size but moved to full-strength ink; squint test then read what/when/where in one pass
- Pitfall: on minimal posters, hierarchy comes from scale AND ink strength — never dim the fact the poster exists to deliver
- Confidence: repeated

### 2026-11-16 | single radial pool as the only ornament
- Situation: type-only poster risked reading as empty rather than composed
- Move: one brass radial-gradient pool at 62% height placed exactly where the setlist starts — the emptiness above it now reads as a staged room
- Pitfall: decoration earns its place only by positioning information; a pool with nothing in it is wallpaper
- Confidence: repeated

### 2026-11-16 | (example entry — pattern reference)
- Situation: event poster where the client insisted on 9 pieces of information (title, 4 acts, date, venue, sponsors, QR, price)
- Move: split into primary read (title + date at extreme scale), secondary grid (acts as a timetable list), and a marginalia rail for sponsors/QR — all 9 items survived, hierarchy made it feel like 3
- Pitfall: fighting the client over information count is lost labor; restructure the reading order instead of deleting content
- Confidence: repeated
