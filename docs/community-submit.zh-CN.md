# 投稿指南：一张图，三句话

> 你不需要会代码，也不需要会 Markdown。会拖图片、会写三句话，就能投。

## 30 秒版

1. 打开 [作品投稿表单](https://github.com/iifzx/design-garden/issues/new?template=community_work.md)。
2. 填标题，选一个类型，写“背景 + 一个取舍 + 一个没解决的问题”。
3. 把一张 PNG / JPG / WebP 拖进“图片”那一节。
4. 勾选授权，提交 issue。
5. 自动检查通过后会生成一个 PR；维护者审核并合并，作品就进入 [/start/ 作品馆](https://iifzx.github.io/design-garden/start/)。

没有 GitHub 账号？可以浏览作品和投票结果，但不能提交或点 👍。注册免费，邮箱就能注册。

## 我们收什么

- 海报、网页、图标、Logo、品牌小系统、幻灯片、插画。
- 一张主图就够；最多 3 张，不要九宫格拼图。
- 真实做过的、自己愿意公开的作品。
- 半成品也可以，只要说明里写清楚“还没解决什么”。

## 我们不收什么

- 别人的作品，或客户还没公开的稿子。
- 纯 AI 拼贴、没有一句说明的图。
- 只有“好看吗”、没有背景的图。
- 二维码、联系方式为主的广告图。
- SVG 文件（第一期只收位图，避免脚本风险）。
- 含个人隐私、客户秘密、未公开品牌名的图。

## 图片规格

| 项目 | 要求 |
|---|---|
| 格式 | PNG / JPG / WebP |
| 数量 | 1–3 张 |
| 单张大小 | ≤ 5 MB |
| 最短边 | ≥ 800px |
| 内容 | 主体完整，不裁掉关键信息；不要纯白截图 |
| 隐私 | 遮掉客户名、手机号、地址、未公开数据 |

GitHub 会在你拖图时自动生成 `https://github.com/user-attachments/assets/...` 链接。自动检查只接受这种 GitHub 附件地址；不要把图片放在网盘或图床。

## 三句话怎么写

按这个顺序写，评审最快：

1. **背景**：给谁、用在哪、为什么做。
2. **一个取舍**：你放弃了什么，为什么。
3. **一个没解决的问题**：哪一块还不满意，想让社区讨论什么。

例子：

> 给小区流浪猫领养日做海报。用一张手绘猫的剪影，因为照片里每只猫都不同，会分散领养信息；但剪影看不出猫的性格，还没解决。

不要写“提升品牌调性”“增强视觉冲击”这类空话。具体场景比形容词有用。

## 评审只看三件事

1. **是不是你的**：版权清晰，客户稿已获公开许可。
2. **能不能看清**：主体、文字、细节在图片里可读。
3. **说明有没有信息**：有背景、取舍、未解决的问题。

不按“专业不专业”打分，也不按粉丝数排序。需要修改时，维护者会在 PR 里指出缺什么；修改 issue 会自动更新同一个 PR。

维护者会尽快处理。如果几天没有动静，可以在 issue 里礼貌追问；不要重复开 issue。

## 授权与署名

- 你保留作品的版权。
- 提交即同意以 **CC BY 4.0** 在作品馆展示，并署你的 GitHub 用户名。
- 用了 AI 生成或 AI 辅助，请在说明里写明；模板里有勾选框。
- 不想公开的客户稿，不要投。

## 投票怎么算

- 投票在 **作品 issue** 上发生，不在网站上直接写票。
- 点 issue 正文的 **👍**（GitHub reaction）就是一张票。
- 一个 GitHub 账号对一件作品只算一票；可以取消或改票。
- 网站每 6 小时同步一次票数；页面上的“票数同步于”是最近一次同步时间。
- 票数用于本月主题的社区评选；不代表专业评审，也不作为唯一依据。

## 常见问题

**没有 GitHub 账号能投吗？**
不能提交，也不能点 👍；可以浏览。注册免费。

**可以投多个作品吗？**
可以，一件作品一个 issue。不要在一个 issue 里塞四张不同的作品。

**可以投网页截图吗？**
可以，但请给完整页面或关键屏，不要只给一张模糊的缩略图。

**可以只放 Behance 链接吗？**
不行。作品馆要能直接显示图片；请把主图拖进 issue。

**作品被合并后还能改吗？**
可以。编辑原 issue 会更新 PR；如果已经合并，维护者会用一个新的 PR 替换 JSON 和图片。

**想删除自己的作品？**
开一个 issue 或直接联系维护者； merged 的作品会从 `community/submissions/` 删除，并重新构建站点。
